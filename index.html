    01Abstract

    Robot interfaces for a general coding agent

    Coding agents pursue a goal over many turns by inspecting state, calling tools, and writing programs. We ask how far a general-purpose coding agent can carry out long-horizon mobile manipulation on a robot without an additional task-specific workflow. We study a design we call simple agent, strong tools and present CARIO (Coding Agents with Robotic Interfaces for Operations).

    A multimodal coding agent serves as the high-level closed-loop policy, with no robot-specific planner, staged workflow, or skill library. Its tools provide visual observation, geometry and body-state queries, and motion control, and in a persistent session the agent chooses its next observation, action, or Python program from the actual results of execution.

    Without demonstrations or robot-specific model training, CARIO reaches mean task progress 0.681 on 50 BEHAVIOR episodes, against 0.520 for a same-model coding-agent baseline, and with identical robot tools, letting the agent decide when to query, act, and run code outperforms a fixed code-block workflow. We also run CARIO on a real wheeled robot and in role-driven restaurant service. A general coding agent with suitable robot interfaces is thus a workable route to long-horizon mobile manipulation.

    02Method

    One loop: observe, act, adjust from feedback

    The coding agent decides what to look at, which work to attempt, and which tool call or program to submit. The runtime dispatches robot requests, executes code in a persistent VM, and returns real outputs and fresh observations. Navigation and manipulation controllers turn accepted requests into motion.

    observe

    Ask for the evidence it needs

    Camera views after travel, RGB-D at a chosen pixel, measured joint posture. Sensing is a decision the agent makes, not a fixed stream.

    act

    Structured calls or whole programs

    robot(method, arguments_json) for a single request, or Python in python_vm that composes robot APIs with branches, loops, and reusable functions.

    adjust

    Read receipts, then look again

    Motion receipts report what the controller reached; new images show what actually happened. Interrupted motions return their endpoint instead of being replayed.

    Motion interface

    Bounded base velocity segments, end-effector pose requests tracked by a dual-arm and trunk QP, gripper commands, bounded joint adjustments, and waiting. The agent picks every route segment and target.

    Execution assessment

    Combine receipts with fresh images to decide what changed and what to do next.

    motion receiptsrecord_progressfinish

    Motion completed ≠ task done.

    A controller can reach its target while the object stays on the floor. CARIO keeps the two apart: receipts describe the hand, images describe the world, and a satisfied finish must cite a consistent placement measurement.

    03Real robot

    Each stage starts from what the last one left

    On a real wheeled robot, the same coding agent and model gather four pieces of fruit from the floor into a basket, then carry the loaded basket to a shelf and set it down. The agent moves on only after seeing the result: all four fruits inside before it grasps the basket, the basket rising with the gripper before it turns, and the basket staying on the shelf after release before it withdraws.

        07Beyond fixed goals

        A restaurant shift, not a checklist

        The instruction gives a role, not a task list: attend to guests based on the situation and keep the restaurant ready for further service. In this service case, Mr. Lin at table C orders a steak to be served as soon as it is ready, and Ms. Wu at table A orders one too and asks the robot to clear an empty plate from table B. None of these jobs is in the instruction: they arrive only through the guests' own words. The run ends with both steaks resting on the ordering tables and the empty plate in the return area.
